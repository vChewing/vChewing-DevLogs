#### 12.7.1 事由（量測，2026-09-27）

逐 Phase 之記述總量（Reqs 卷 Phase 篇 ＋ `DevReqsHistory.md` 該列；P250 起另加本檔條目）之十年段平均：**P160–169 ＝ 6,424 chars／phase** → **P200–209 ＝ 15,730**（第一次跳變，2026-09-13）→ **P240–249 ＝ 25,172** → **P250–261 ＝ 22,690（另加本檔新條目 37,941 chars）**，計 **3.7 倍**。同期 Reqs 卷之單篇中位數 5,487 → 12,787。

**兩個關鍵量得**：① **拼音狂打（P148／P155）不是轉折點**——該兩篇為 3,008／3,399 chars，低於當時中位數；② **本檔開頭之 22 條逐 Phase 記述（37,941 chars ＝ 全檔 24.2%）係 P250 起才長出來的**（`git show 7b69bf2:KnowledgeMemo4LLM.md` 之開頭部一條也無）——即**本檔文首〈沿革不再寫入本文檔〉（2026-09-17 修訂）之規則被違反**，而非風格自然演化。

#### 12.7.2 通則：一處一寫（One fact, one home）

| 事實之類別 | 唯一落點 | 上限 |
|---|---|---|
| durable 規格／判準／API 名／常數／根因／通則 | **本檔**（住 `KnowledgeMemo_SubArticles/` 之相關分卷；索引與鐵律住 `KnowledgeMemo4LLM.md`） | 每條 ≤ 300 chars |
| 本 Phase 之決定性取捨、證據、界線 | **Reqs 卷該 Phase 篇** | 見 12.7.3 |
| 索引（一句話） | **`DevReqsHistory.md`** | ≤ 300 chars／列 |
| 長篇推導、量測、方案比較 | **`Research/`**（維持現狀，不動） | 不限 |

**下游只准引用、不准複述**：Phase 篇寫「判準六條見規劃書 §3.2（v7）」，**不得**把那六條再抄一遍；`DevReqsHistory` 列寫「詳 P261」，**不得**把該篇壓成 3,000 字的第二正本；本檔寫「見該卷 P2xx」，**不得**重述其敘事。**四份文件重複同一段敘事是最大的單一浪費**（實測 P261：Reqs 12,905 ＋ History 3,112 ＋ 本檔 4,015 ≒ 20,032 chars 講同一件事）。

#### 12.7.3 預算

- **Reqs 卷 Phase 篇**：修補型（1–3 檔、零設計）**≤ 2,500**；標準 **≤ 5,000**；大型／系列／規劃 **≤ 8,000** chars。**超標須在交差回報中寫明一行理由**。
- **預算之實證地板（2026-09-27 回溯套用時量得）**：把一篇原篇中所有「事實符記」（commit hash／檔名／反引號識別字／數字／混合識別字）抽出，其**字面本身**即佔全部原篇之 **22%**（P241–P261：316,991 chars 中原篇符記淨成本 **69,933**）。而一篇寫得再緊，事實符記仍需彼此之框（反引號、分隔、六節骨架）⇒ **實得約為地板之 2.1 倍**。故：**事實密度高之 phase 無法盡達 8,000**——P241–P261 之實績為 3,259～11,995 chars，其中 11 篇須以一行理由超標。**預算之真正作用在於抑制「儀式」與「重複」，不在於逼近地板**；寧可超標並記明理由，不得為達標而刪事實。
- **`DevReqsHistory.md` 每列 ≤ 300 chars**、**一列**（不得一個 Phase 佔多列）。
- **本檔之各分卷**（`KnowledgeMemo_SubArticles/NN-Topic.md`）**每卷 ≤ 12,000 chars**（2026-10-15 拆分時立此尺，量尺為 `housestyle_audit.py` 之 `SUB_ARTICLE_MAX`）。其故：拆分前該備忘錄為單一 188,646 chars 之長檔，AI Agent 一見即「寧願只讀一部分」、遂於 house style／lintFormat／localized file content sorting 一類細節上疏漏；**故每一卷都必須小到能整卷讀完**。索引本體一併列報，不受此限。
- **本檔每 Phase 淨增 ≤ 1,500 chars**，且**必須**屬「現況」或「施工注意事項」。逐 Phase 敘事一律禁止。
- **通則（★ 條）**：僅在**確為 durable 且本文檔尚無同一條**時新增，每條 ≤ 300 chars，**只寫一份**（寫入本檔即不得再抄進 Phase 篇）。

#### 12.7.4 Phase 篇固定骨架

```markdown
# Phase NNN

Assignee: Model（Harness）。

> 狀態：完工（日期）｜提交 hash｜測試基線一行。

## 手術範圍        ← 表格：落點／檔／行數
## 要解決的問題     ← ≤ 3 bullets；根因一行
## 落點與理由       ← 決定性取捨；被否決之方案一行帶過
## 驗證            ← 最終綠燈一行 ＋ 關鍵數字表
## 已知界線         ← ≤ 5 bullets，一行一條
## 未動             ← 一行列舉
```

- `## 前導 Phase` **降為狀態行內之引用**（如「依 P250 §3.2」），**不另立小節**；確需敘述依賴關係時，以一行表列 `P250 → P251–P259 → P260 → 本 phase`。
- **多 Task 之 phase**：Task 只在「手術範圍」與「驗證」各佔一列；**骨架之各小節在 phase 層只出現一次**——**嚴禁**逐 Task 重套模板（P259 之六個 Task 即重套六次，單一 phase 達 39,461 chars）。
- **分隔線之唯一合法用途**（2026-09-27 事主明示）：**`--------------------`（恰 20 個連字號）只准出現在 Phase 與 Phase 之間**——置於 `# Phase NNN` 之上一行，且其上下各一空行。**Phase 篇之內部則不得出現任何以連續 `-` 組成之段落分割線**（無論是 `---` 或任何長度）；小節之區隔一律靠標題，不靠橫線。**表格之表頭分隔列 `|---|---|` 並非分隔線**，不受此限（亦**不必**為此改寫成 `|:--|`）。
  **全庫現況（2026-09-27 清畢）**：Reqs 各卷之 20 連字號共 **233 處、全數落在 Phase 分界**；**篇內橫線 0 處**。共修 12 處早年異常：3 處 20 連字號誤用（`Reqs_0041-0050.md` 篇內 1 處刪除、`Reqs_0101-0110.md` 檔尾懸空 1 處刪除、`Reqs_0211-0220.md` 2 處分界線由 `---` 正規化）＋ `Reqs_0211-0220.md` 之 P219→P220 分界線缺漏 1 處補上 ＋ **篇內橫線 8 處刪除**（`Reqs_0000-0010.md` 5、`Reqs_0011-0020.md` 1、`Reqs_0041-0050.md` 1、`Reqs_0071-0080.md` 1）。**全部為純格式刪修，一字未改。**

#### 12.7.5 應廢除之項目（逐條，皆為純 token 浪費）

1. **本規劃書之版本帳**：正文**不得**寫「已回寫 vN」「重排後續」；版本號只在 `Research/` 該檔之〈修訂沿革〉內維護。
2. **§8.0.1 三步之執行記錄**（對帳／回寫本文／重排後續）：**不寫**。對帳之**結論**（差異清單）併入正文；過程不寫。實測此儀式佔 P251–P261 卷 **22,678 chars ＝ 14.6%**。
3. **CI 逐輪敘事**：結案後只留**一行**（`四條 workflow 全綠；第 N 輪紅燈之根因在測試之按鍵域`）＋ run／job ID。逐輪症狀與診斷字串若確有教學價值，寫成**本檔之〈施工注意事項〉一條**，不寫進 Phase 篇。
4. **`byte-sync`／`shasum`／測試基線之逐檔輸出**：本檔已立常設宣告（兩倉 `Sources`＋`Tests` 逐檔 SHA-256 須全同），Phase 篇只寫一行（`I2 通過（N 檔全同）`）。**空操作亦不寫一節**（P259 曾有一節標題直書「本節為空操作」）。
5. **`未動`／`已知界線` 之窮舉**：各 ≤ 5 條、一行一條；**「明列，不隱藏」之態度以「有界」體現，非以「冗長」體現**。
6. **`補記／追加／追記／第 N 輪`**：**禁止新開小節**；後續輪次**就地修訂**受影響之段落（同一件事只留最終版）。若後續輪次係**獨立交付物**，另開 Phase 編號並照同一骨架寫（此制本已存在）。實測 P241 有此類小節 15 個（51,537 chars）、P245 有 9 個。
7. **事主原文**：只留**一句**決定性引文（≤ 120 chars，且標明「事主原文」），其餘改寫；**不得**連續堆疊多段原文。
8. **自我指涉**：「本 phase 之完整記錄見 `…`」（指向的正是讀者眼前這份）一律刪。
9. **`Research/` 之複述**：規劃書內容一律引用，不重述。
10. **他語系之出貨文案**：**不得**為了「只用 zh-Hant」而把 zh-Hans／en／ja 之**逐字原文**改寫成「同義對位之敘述」。**語言之鐵律只管「正文」，不管「引句」**——引句本身即事實（實際出貨之文案），改了就是偽造。以緊湊表格逐字呈現即可（zh-Hans 之簡化字形、ja 之假名、en 之原句皆然）。**本條係 2026-09-27 回溯時踩到之坑**：當時曾因誤解而刪去 P241／P245／P249／P259 之四語系原文，後經回補。
