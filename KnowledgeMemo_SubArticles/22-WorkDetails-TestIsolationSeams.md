# 12.6 工作細節附註（三之補）：測試隔離之縫與其收束

> 本卷於 2026-10-15 自 `18-WorkDetails-BuildAndTest.md` 析出（該卷已逾 12,000 chars 之限），
> 收 P314–P316 之四條新條；四條依序為索引續號 831、832、833、834。

- **★ 測試目標之 `.serialized` 分佈與其四類真因（2026-10-15，P314 量測）**：正本倉 768 支／71 套；載 `.serialized` 者 **60／92 檔**。四類真因——**(A)** 行程級可變偏好容器（`UserDefaults.current`／`.unitTests`／`.pendingUnitTests`，機制住 `Deps/VanguardSwiftExtension/Sources/SwiftExtension/SwiftFoundationImpl.swift:207-228`）；**(B)** 行程內可變**靜態**（`PrefMgr.sharedSansDidSetOps`／`LXFacade.factoryTrie`／`lxCassette`／`lxPlainBopomofo`／`SessionHost.shared`）——**B 才是 `LibVanguardTests` 根 suite 之主因**；**(C)** 可寫落盤區之**固定檔名**共用；**(D)** 根 suite 之**繼承慣性**（`POMTestSuite` 之 32/33 即此類）。五個目標（`HomaTests`／`TrieKitTests`／`BPMFVSTests`／`BrailleSputnikTests`／`ResourceLocatorTests`）無 A／B／C 之真因、可逕撤；`ArimitsuTests`（35 支、3 個 `@Suite` 全無 `.serialized`、現已並行且全綠）為倉內反證。**兩處 `UserDefaults.standard` 之洩漏**：`Sources/Shared/PrefMgr_Core.swift:563`（致遷移測試須直接佈置真機網域）、`Sources/LexiconAssembly/vChewingLXAssembly_Common.swift:153`（熱路徑日誌）。**全倉 127 處 `@AppProperty` 共用單一出入口** `public var container: UserDefaults { .current }`（`SwiftFoundationImpl.swift:251`）⇒ 隔離縫開於此即**無泛型傳染**。研究稿住 `Research/Phase314_Research_TestIsolationSeams.md`。**（P314 手術後）** 本條所引之 `SwiftFoundationImpl.swift:207-228` 區塊與 `:251` 之 `container: UserDefaults` 已刪除、兩處 `.standard` 洩漏已收口；現行形見下一條。
- **★ 偏好容器與使用者資料 I/O 之兩道縫（2026-10-15，P314 施行）**：`UserDefaults` 之行程級間接層（`UserDefaults.current`／`.unitTests`／`.pendingUnitTests`）**整塊刪除**，代之以 `Deps/VanguardSwiftExtension/Sources/SwiftExtension/DefaultsStore.swift` 之存在型別協定 `DefaultsStore`（`object(forKey:)`／`set(_:forKey:)`／`removeObject(forKey:)`；三項皆 `nonisolated`——該 package 之 `Package.swift` 帶 `.defaultIsolation(MainActor.self)`，不標即被綁上 `MainActor`）＋ `UserDefaultsStore`／`InMemoryDefaultsStore`；解析點為 `OSUtils.defaultsStore`（與 `OSUtils.isRunningUnitTests` 同住 `OSUtils`；**逐次求值、無快取**，故「換容器即時生效」之性質保住）。`AppProperty.container` 僅改一行即完成收口 ⇒ **全倉 127 處 `@AppProperty` 之宣告端零改動，泛型未必需**。使用者資料之 I/O 另走 `Sources/LexiconAssembly/UserDataLocator.swift` 之 `UserDataLocator`（`isBackedByFileSystem`／`exists`／`read`／`write`／`append`／`remove`／`byteSize`；`DiskUserDataLocator`／`InMemoryUserDataLocator`／`DisabledUserDataLocator` 三態），解析點為 `LXAssembly.userDataLocator`；`LXCoreEX`／`LXAssociates`／`LXReplacements`／`PerceptionPersistor` 之落盤、`LXFacade` 之六處可讀性檢查、`LXCassette` 之載入、`LXConsolidator` 之三函式全數改道（卡帶為保串流而分岔：磁碟走 `FileHandle`、記憶體走 `ByteLineIterator(data:)`；整理器則把「改檔案」化為「改位元組」），而**路徑決策仍留在 `LXFacade`**（成員只負責 I/O，故協定不引入目錄語意）。四入口另備 `using locator:` 參數（預設取全域），測試得藉此指定容器而**不置換全域**。**測試側之新慣用語**：`OSUtils.defaultsStore = InMemoryDefaultsStore()` ＋ `OSUtils.isRunningUnitTests = true`、`LXAssembly.userDataLocator = InMemoryUserDataLocator()`；自此 P302 所言之「同一片硬碟區域」之固定檔名（如 `POMFileHandleTests` 之六個 `test_pom_*.json`）只活在該測試用例自己的記憶體容器內，且五個零真因目標已撤 `.serialized`。**界線**：兩道縫皆係行程級可變全域（換容器仍是全有全無），故「逐型別實例注入」仍是解鎖跨套房並行、進而撤 `LibVanguardTests` 根 suite 之 `.serialized` 的必要條件。**記憶體容器之獨有陷阱**：`UserDef.kAppleLanguages` 之預設值是**空陣列**，生產環境之所以讀得到語系，全靠 `UserDefaults` 續查全域網域（`AppleLanguages` 住 `NSGlobalDomain`）；`InMemoryDefaultsStore` 沒有這層後援，故凡「值由系統網域補上」之鍵，直取下標者一律在測試中越界（`CtlSettingsUI` 與 `PhraseEditorUI` 各現一次）——一律改 `.first ?? 預設值`（現行正解為 `PrefMgrProtocol.effectiveAppleLanguage`）。詳 `Research/Phase314_Research_TestIsolationSeams.md`。
- **★ 兩道縫之實例化：偏好容器與資料 I/O 隨實例走（2026-10-15，P315 施行）**：P314 把縫釘在行程級全域上（`OSUtils.defaultsStore`／`LXAssembly.userDataLocator`），換容器即全有全無，兩個套房真並行仍互搶同一顆全域 ⇒ 本 phase 把縫下推到**實例**。`LXFacade` 收 `public let locator: any UserDataLocator`（`init` 添 `locator:`，預設取全域）並**派給**五個使用者語言模組（`lxUserPhrases`／`lxFiltered`／`lxUserSymbols`／`lxAssociates`／`lxReplacements`）與 `lxPerceptor`（只自用而不派，則轉檔器之落盤仍回看全域，等於做了一半）；`LXPerceptor`／`PerceptionPersistor` 添 `locator:`；三型 LM 之就地整理加 `isBackedByFileSystem` 閘（記憶體後端無檔可整，強行整理會使兩種通道給出不同內容）；卡帶係唯讀資源且載入入口為**靜態**（`loadCassetteData(path:)`），故僅 `open(_:using:)` 逐次指定，未收儲存屬性。偏好側：`DefaultsStore` 改繼承 `Sendable`（`AppProperty` 以儲存屬性持有之故），`AppProperty` 由「逐次求值 `container`」改為**建構時捕獲** `public var store`（不得為 `let`——126 處係於 `PrefMgr.init(store:)` 內逐一改綁），而「換全域容器 ⇒ 換一份管理器」之舊語義移交 `sharedSansDidSetOps`：由 `static let` 改為依 store 身分（`ObjectIdentifier`）快取之計算屬性、`NSMutex` 護衛。**同一個 phase 內兩處對「捕獲 vs 逐次」給出相反答案，皆有據**：包裝器**必須捕獲**（否則實例無從綁定自己的容器）、共用管理器**必須逐次解析**（否則換過容器之套房仍與舊實例對話）——只有不注入者需要即時性。`PrefMgr` 另收 `public let store`，`migrateDeprecatedSettings()` 以之為域（否則遷移在 A 容器、讀寫在 B 容器）。**`LXFacade.prefs`** 原為建構時捕獲 `PrefMgr.sharedSansDidSetOps`；一旦後者改依容器解析，此處若仍捕獲，「在 `withIsolatedPrefs` 內換容器」之 `LXFacade_FuriousZhuyinwenTests` 兩支即紅（實測）⇒ 改為未注入時逐次索取（`injectedPrefs ?? PrefMgr.sharedSansDidSetOps`）。**測試側之新慣用語**：套房自持 `let locator = InMemoryUserDataLocator()` 並於建構時傳入（**不再置換全域**），POM 五套房（`POMEncoding`／`POMFileHandle`／`POMIndexedRetrieval`／`POMJournalReplay`／`POMLockDiscipline`）與 `PrefMgrFuriousTypingMigrationTests` 共撤六處 `.serialized`；新 5 支證明「同一路徑、兩實例互不相屬」與「全域後端未曾見過該路徑」（後者是『真的沒回頭』之唯一可觀察證據）。**陷阱**：ⓐ `AppProperty.store` 須 `var`；ⓑ `LXPerceptor` 之標籤順序即宣告順序，機械替換若把 `locator:` 插在參數列首即得 `argument 'capacity' must precede argument 'locator'`，須插在參數列尾；ⓒ 多行引數列之字串替換會同時命中宣告與呼叫。**界線**：類 B 靜態（`LXFacade.factoryTrie`／`lxCassette`／`lxPlainBopomofo`、`SessionHost.shared`）仍在，`LibVanguardTests` 之 `.serialized` 未撤；`UserDef` 之靜態 API 仍以全域為域，故 `UserDefExchangeTests` 仍載 `.serialized`。全量 776 支／73 套全綠（不帶 `--no-parallel`）。詳 `Reqs4LLM/Archive_P301-P400/Reqs_0311-0320.md` 之 `# Phase 315`。
