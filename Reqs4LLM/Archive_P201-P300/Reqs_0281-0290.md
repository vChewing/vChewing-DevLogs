## 要解決的問題

- **死引**：原 §三 有 `三.1`–`三.4` 四小節，重寫後 §三 之下再無小節編號，而倉根 `README.md:59`／`:112` 與 `README-CHS.md:59`／`:112` 皆以「見[助手之說明 §三.1]」指取得管道 ⇒ 節號成死引（連結目標本身有效）。病灶＝該 session 之交叉引用掃描獨漏 `*.md`。
- **知識流失**：原 §三.3 載明「**何以在 plugin 內呼叫、而非於 `Makefile` 之 plugin 呼叫之後補做**」——`--archive` 會在同一趟 plugin 執行內完成組裝與封存，事後補做會漏掉 `.xcarchive`。新版只留「簽章之前」那半條；`.xcarchive` 那半條無測試守著，是後人把收錄移到 plugin 之後時必踩的坑。
- **宿主缺陷（`P246` 之錯，非該 session 之過）**：`mkdirSync` 對屬性字典傳 `null`，JXA 橋接成 `NSNull`，Foundation 對之呼叫 `-count` 即拋 ⇒ 無 `dist/fixtures` 之樹上 `make audit` 必炸（`-[NSNull count]: unrecognized selector sent to instance …(-2700)`、RC=2）。
- **陳舊註解**：`version.txt` 之檔名與 `dom-smoke.test.js` 之頁數（兩處）皆與實況不符。

## 落點與理由

- 死引採「在助手 README 恢復小節」而非改四處引用：較貼近 `P249` 之原意，且不動兩份倉根 README。`三.1` 專載取得管道（四處引用所稱者）、`三.2` 收 npm 版之緣由；通則括註原在篇末、易讀成 `三.2` 之一部分，故上移為 §三 導言。
- 版本示例改寫為 `<version> (<build>)` 而非填值：填值者必再陳舊——此檔已錯過一輪。
- 宿主修法取 `$()`（JXA 之空 ObjC 物件）：與省略參數實測等效，惟明寫保留原呼叫形狀，並加註「`null` 會被橋接成 `NSNull`」以免回改。
