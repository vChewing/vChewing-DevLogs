## 待定事項

**B｜`Typewriter` 的型別要不要一併改？** 依定案，`Typewriter` 只改 package／target 名，型別名不動。但該模組內仍有約 8 個含 "Typewriter" 的型別（`TypewriterProtocol`、`BPMFFullMatchTypewriter`、`MixedAlphanumericalTypewriter`、`CassetteTypewriter`、`RomanNumeralTypewriter`、`HaninSymbolTypewriter`、`CodePointTypewriter` 等）與函式 `handleTypewriterSCPCTasks`。結果會是「`OSNeutralAssembly` 模組內滿是 Typewriter」。若定案為「一併改」，本 phase 須連同這些型別、其檔名與測試一併處理；若定案為「接受現狀」，本 phase 到此為止。

### 〈待定 B〉定案（2026-09-13）

**接受現狀：`Typewriter` 系型別名一律不動。** 理由有三：

1. 事主的更名對照表已明文將 `Typewriter` 限定為「Swift Package 名稱與 Target 名稱，**不是** Struct / Class / Protocol Type 名稱」——此即定案本身，本 phase 只是確認而已。
2. 該型別群與 `handleTypewriterSCPCTasks` 的新名無任何既定方案；強行發明會引入未經裁定的命名（尤其 `TypewriterProtocol` 究竟該叫 `OSNeutralSessionProtocol` 還是別的，屬語意決策而非機械改名）。
3. 模組層與型別層的命名得以分離：`Sources/OSNeutralAssembly/Typewriter/` 子目錄與其檔名（`Typewriter_*.swift`、`TypewriterProtocol.swift`）一併保留，使「Typewriter」收斂為**該子系統的領域術語**（打字態械族）而非模組名。

故第 4 項驗收之「零殘留」以**排除該群**為條件成立。

## 要解決的問題與大概需求方向
