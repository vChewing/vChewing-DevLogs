## 要解決的問題

「被迫 serialized」是**兩道防線同時上著**、且互不替代：CLI 層 `swift test --no-parallel`（`Makefile:157`；`vChewing-macOS/Makefile:546` 同旨）只治同一次執行內之多個測試目標；型別層之根 suite `.serialized`（`Tests/LibVanguardTests/LibVanguardTests_Root.swift:35`、`Tests/LexiconAssemblyTests/POMBasicTests.swift:13-14`）只治子樹內。施行前全倉 **60／92 個測試檔**載 `.serialized`。

裁定：**目的 1 成立、必要，但不足以單獨成事；目的 2 成立且成本遠低於目的 1；「很多類型需要 Associated Type 或 Generics」不成立。**

理由之核心：枷鎖不是「依賴 `UserDefaults` 這個型別」——`@AppProperty` 早已經由 `UserDefaults.current` 間接讀寫。枷鎖是**該間接層本身係行程級可變全域**，外加**兩處繞過它直讀 `.standard`**：`Sources/Shared/PrefMgr_Core.swift:563`（`migrateDeprecatedSettings()`；致 `Tests/SharedTests/PrefMgrFuriousTypingMigrationTests.swift` 必須直接對 `.standard` 佈置與清理，即單元測試正在讀寫開發者真機偏好檔）與 `Sources/LexiconAssembly/vChewingLXAssembly_Common.swift:153`（熱路徑 `vCLMLog` 直讀 `.standard`，而 `Sources/Shared/Shared.swift:21` 同義讀取走 `.current`）。泛型之憂可解：全倉 127 處 `@AppProperty` 全經同一個 `@propertyWrapper` 進入，縫只要開在 `container` 一行 ⇒ **宣告端零改動**。

真正的枷鎖有四條：**A** 行程級可變偏好容器；**B** 行程內可變靜態（`PrefMgr.sharedSansDidSetOps`／`LXFacade.factoryTrie`／`lxCassette`／`lxPlainBopomofo`／`SessionHost.shared`）——**B 才是 `LibVanguardTests` 根 suite 之主因**；**C** 可寫落盤區之固定檔名共用（`POMFileHandleTests` 之六個固定檔名全落 `NSTemporaryDirectory()`）；**D** 歷史慣性（根 suite 之 `.serialized` 被整棵子樹繼承，真因早已不在——五個目標之測試全無 `UserDefaults`／`FileManager`／`.shared` 引用）。

## 落點與理由

**縫一（`DefaultsStore`）**：存在型別 `any DefaultsStore`，非泛型。協定三項要求皆 `nonisolated`——`SwiftExtension` 帶 `.defaultIsolation(MainActor.self)`，不標即被綁上 `MainActor`，而 `PrefMgr` 之屬性存取發生在任意執行緒。`AppProperty.container` 改為 `public var container: any DefaultsStore { OSUtils.defaultsStore }`，**仍逐次求值、無快取**——`@AppProperty` 之「換容器即時生效」性質必須保住。行程級 API 遷入 `OSUtils`（合 17-WorkDetails-ProcessAndLint.md 之「系統級 API 一律住 `OSUtils`」）。

**縫二（`UserDataLocator`）**：協定共七項要求（`isBackedByFileSystem` 屬性 ＋ `exists`／`read`／`write`／`append`／`remove`／`byteSize` 六支方法），**不含目錄語意**——五個字串路徑成員之路徑決策早已發生在 `LXFacade` 內（`:469`／`:501`／`:553`／`:588`／`:616`），成員只負責搬位元組。`append` 不可省：POM 之 WAL 原本用 `FileHandle(forWritingTo:)` 逐筆追加，若協定只有讀寫，記憶體實作得自行讀-改-寫並喪失追加語意。**卡帶與就地整理器亦下推**：`LXCassette` 之 `fileExists` ＋ `FileHandle` 與 `LXConsolidator` 之三函式原握 `FileManager`，一併改道；卡帶為保串流而分岔（磁碟走 `FileHandle`、記憶體走 `ByteLineIterator(data:)`），整理器則把「改檔案」化為「改位元組」（`fixEOF` 之空檔特例隨之消失），四個呼叫點之 `isBackedByFileSystem` 閘遂撤——否則兩種通道會給出不同內容。四入口並添 `using locator:` 參數（預設仍取全域），使測試得以指定容器而不置換全域。

**測試側**：新慣用語 `OSUtils.defaultsStore = InMemoryDefaultsStore()` ＋ `OSUtils.isRunningUnitTests = true`，取代 `UserDefaults.unitTests = .init(suiteName:)` ＋ `pendingUnitTests = true` ＋ `removeSuite`。POM 五套房之 `init`／`deinit` 換上／還原 `LXAssembly.userDataLocator`，六個固定檔名自此只存在於該測試用例自己的記憶體容器內——**類 C 之實體消失**。

**隔離修飾詞一律採成員式**：型別層 `nonisolated` 係 6.2+ 語法、5.10 拒收；`FileHandle` 拋錯 API 起自 10.15.4，改走 10.9 相容層。二事僅 legacy 側現形（研究稿 §8.6）。

**消費端補課**：縫一刪的是掛在 `UserDefaults` 上之擴充，`vChewing-macOS` 各套件之呼叫點遂一併失效，同 phase 內補 23 檔（`current` 36 處、`pendingUnitTests` 36 處、`unitTests` 13 處）。補課另暴露真缺陷：`UserDef.kAppleLanguages` 預設值是**空陣列**，生產環境靠 `UserDefaults` 續查全域網域（`AppleLanguages` 住 `NSGlobalDomain`）才有值；記憶體容器無此後援，故 `appleLanguages[0]` 在 `CtlSettingsUI`／`PhraseEditorUI` 兩處越界崩潰。`PrefMgrProtocol` 遂加 `effectiveAppleLanguage`（空陣列時退回 `Locale.preferredLanguages`），六處直取 `[0]` 者一律改道。

**駁回**六案（全 `FileSystemProtocol`、泛型化 `AppProperty`、只改預設 suite 名、只撤 `.serialized`、`@TaskLocal`、`volatileDomain`），理由見研究稿 §四。

## 要解決的問題

P314 把手術做完、卻把縫**釘在行程級變數上**：`OSUtils.defaultsStore` 與 `LXAssembly.userDataLocator` 各是一顆全域，換容器是全有全無。於是兩個套房真並行時仍會互搶同一顆全域——而 POM 五個套房的資料**早已全在記憶體**，卻仍揹著 `.serialized`，只因那顆全域一次只能服務一個套房。本 phase 把兩道縫下推到**實例**，使「誰用哪一顆後端」成為建構時之事，而非行程狀態。

## 落點與理由

**軌 A（I/O 縫下推）**：`LXPerceptor` 與 `PerceptionPersistor` 本已具 `init(baseURL:)`，添 `locator:` 即接上；`LXFacade` 收一顆 `locator` 後**不只自用**，還須派給五個使用者語言模組（`lxUserPhrases`／`lxFiltered`／`lxUserSymbols`／`lxAssociates`／`lxReplacements`）與 `lxPerceptor`——否則「實例化」只做了一半：轉檔器的落盤仍回看全域。卡帶係唯讀資源、且載入入口是**靜態**（`LXFacade.loadCassetteData(path:)`），故該兩處仍走全域；實例路徑（`initializeFactoryDict` 一族）則改傳實例後端。三型 LM 之就地整理加 `isBackedByFileSystem` 閘：記憶體後端沒有檔案可整理，強行整理只會讓兩種通道給出不同內容。

**軌 B（偏好縫下推）**：`AppProperty` 之 `container` 於 P314 是**逐次求值**（`{ OSUtils.defaultsStore }`），那正是「換容器即時生效」之來源，卻也是實例化的障礙——逐次求值意味著實例永遠黏著全域。改為建構時捕獲（`public var store`），並把「即時性」移交給真正需要它的那一處：`sharedSansDidSetOps` 由 `static let` 改為**依 store 身分快取**之計算屬性（`ObjectIdentifier`；`NSMutex` 護衛），故「換全域容器 ⇒ 換一份 PrefMgr」之舊語義一字不減。

**同一個 phase、兩處相反之取捨，且皆有據**：屬性包裝器**必須捕獲**（否則實例無從綁定自己的容器）；共用管理器**必須逐次解析**（否則換過容器之套房仍與舊實例對話）。此二事看似矛盾，實為「誰需要即時性」之分工——只有不注入者需要。

**`PrefMgr` 自己也要一顆 `store`**：`migrateDeprecatedSettings()` 讀的是舊鍵（`"FuriousTypingEnabled"` 等），與 126 項宣告同域——若它仍走全域，遷移就會在 A 容器、讀寫卻在 B 容器。故 `PrefMgr` 收 `public let store`，遷移以之為域。

**`LXFacade.prefs` 之捕獲/解析**：原為 `private let prefs = PrefMgr.sharedSansDidSetOps`（建構時捕獲）。一旦 `sharedSansDidSetOps` 依容器解析，此處若仍捕獲，則「在 `withIsolatedPrefs` 內換容器」之既有測試（`LXFacade_FuriousZhuyinwenTests`）就會與舊實例對話——實測兩支轉紅（旗標與查詢結果皆不符）。正解：未注入時**逐次**索取（`injectedPrefs ?? PrefMgr.sharedSansDidSetOps`），注入時方固定。此修一併讓 `LXFacade` 具備偏好注入之能力。

**測試側**：POM 五套房改自持後端（`struct` 與 `final class` 套房皆然：Swift Testing 為每一測試用例新建一份套房實例），故 `.serialized` 撤得乾淨；`POMJournalReplayTests` 之兩支檔案級輔助函式（`writeReplayJournal`／`writeReplaySnapshot`）添 `locator:` 參數。新增兩套 5 支用例之證明重點不在「能存能讀」，而在**兩個實例對同一路徑互不相屬**、且**全域後端未曾見過該路徑**——後者是「真的沒回頭」之唯一可觀察證據。

**陷阱（實錄）**：① `AppProperty.store` 不可為 `let`——126 處係於 `PrefMgr.init` 內逐一改綁，故須 `var`（`didSet` 不受影響，因其掛在 `wrappedValue` 上）。② `LXPerceptor` 之標籤順序即宣告順序，機械替換若把 `locator:` 插在參數列首，即得 `argument 'capacity' must precede argument 'locator'`——須插在括號**前緣之前**、即參數列尾。③ 測試輔助函式之參數列改寫須以括號配對為準；以字串替換處理多行引數列時，宣告與呼叫會同時命中（實測把 `, locator: locator)` 也貼進了宣告尾巴）。
